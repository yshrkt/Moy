# ログローテーション

設定画面の「ログローテーション」で自動処理のON／OFF、ファイルサイズの目安、過去ログの保存世代数を設定できます。初期状態はOFF、サイズは10 MB、過去ログは5世代です。1 MBは1,000,000 bytesです。

対象は`~/Library/Logs/Moy`直下の番号なし`.log`通常ファイルです。サービス定義とは照合せず、削除済みサービスのログも対象です。独自の保存先でも、このディレクトリ直下の`.log`は対象になります。サブディレクトリ、シンボリックリンク、ディレクトリ外のログは対象外です。

ONにすると専用LaunchAgentが登録され、登録時とログイン時、その後は1時間ごとに確認します。Moyを終了しても処理は続きます。スリープ中は処理されないため、サイズは厳密な上限ではありません。OFFにすると専用LaunchAgentを解除しますが、ログや過去ログは削除しません。この内部ジョブはサービス一覧には表示されません。

ログはサービスを停止せずにコピーし、元ファイルを空にするcopytruncate方式です。コピーと切り詰めの間に書かれたログは失われる可能性があります。元ログの所有者・権限とinodeを維持し、過去ログは`<元ファイル名>.1`、`.2`…として保存します。`.1`が最新です。世代数には現在のログを含まず、圧縮は行いません。世代数を減らした場合、次にそのファイルがローテーションされるときに余分な世代を整理します。

コピーや過去ログの配置に失敗した場合、元ログを空にしません。ユーザー権限で処理できないファイルは管理者権限に切り替えず、失敗として記録し、他のファイルの処理を続けます。直近の失敗は設定画面を開いたときや、設定画面に戻ったときに確認できます。次のチェックが正常に完了すると失敗記録は消えます。

設定は`~/Library/Application Support/Moy/log-rotation.json`、失敗記録は同ディレクトリの`log-rotation-report.json`に保存します。サービスの`services.json`とは別です。

アプリを移動した場合は、移動先のMoyを起動すると内部ジョブの実行パスを更新します。登録・解除が失敗した場合はエラーダイアログを表示し、実際の登録状態をスイッチと保存設定に反映します。登録に失敗して未登録ならOFF、解除に失敗して登録が残っていればONとなり、スイッチで操作をやり直せます。登録状態も確認できない場合は直前の表示を維持してスイッチを無効にするため、原因を解消して設定画面を開き直してください。「更新」「再試行」ボタンは設けません。
